# Blocks

How Storymap reads a block from the game's assets and draws it: its codes, its colour on the game's map, its texture colours, its climate and season tint, its cube faces and its shapes, what preparing keeps of it, and the pictures the isometric view draws it with. The assets themselves, and how the map is drawn and tiled, are in [`rendering.md`](rendering.md); sourcing conventions are the same as in [`save-format/README.md`](save-format/README.md).

## Block codes

A save names its blocks by code (`rock-granite`), and nothing in a code says which file defines it, so every block type is expanded into its codes as the game does it, by [`src/vs/BlockTypes.zig`](../src/vs/BlockTypes.zig) *(Source: vsessentialsmod's [`RegistryObjectTypeLoader.cs`](https://github.com/anegostudios/vsessentialsmod/blob/06673b67318e002332b6aa8b3d0308f11d2aba99/Loading/RegistryObjectTypeLoader.cs) and [`RegistryObjectType.cs`](https://github.com/anegostudios/vsessentialsmod/blob/06673b67318e002332b6aa8b3d0308f11d2aba99/Loading/RegistryObjectType.cs))*:

- **A block type** is a file in any domain's `blocktypes/`, with a `code` in the file's domain unless it names another. One with `enabled: false` (or `0`) makes no blocks. `inheritFrom` lays the file over another one first.
- **Variant groups** each give a list of states: their own `states`, or a world property's variants (`loadFromProperties: "block/rock"` is `worldproperties/block/rock.json`, in the `game` domain unless it names another; `loadFromPropertiesCombine` joins several). Groups that multiply (the default) give every combination of their states; groups that add give one block per state. A block's code is the type's code and its states, joined with `-`; an empty state adds nothing. `selectiveMultiply` splits one state of another group; nothing in 1.22.7 or Primitive Survival uses it.
- **`skipVariants` and `allowedVariants`** then filter the codes, by exact code or by wildcard, as `…ByType` keys are matched (below); none in 1.22.7 or Primitive Survival is a regular expression.
- **`…ByType` properties** take a value per variant: in `blockmaterialByType: { "*-snowy": "Snow", "*": "Soil" }`, the first key matching the block's code gives `blockmaterial` (an object merges into one already there), and `…ByType` properties inside are resolved the same way. Keys are wildcards, `*` matching any run of characters with letters in either case, or regular expressions after `@`, matching the whole code with case: the game's and Primitive Survival's use only groups of alternatives, `.` and `*` (`"@.*-(aged|veryaged)-.*"`), which is all Storymap supports. `{rock}` in a string is the variant's state of the `rock` group (`{wood|rock}`, either). *(Source: vsessentialsmod `RegistryObjectType.solveByType`, vsapi [`WildcardUtil.cs`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Util/WildcardUtil.cs) and `RegistryObject.FillPlaceHolder`.)*
- **Patches aren't applied.** Mods can patch block types, but no patch in 1.22.7 or Primitive Survival changes which codes there are.

The result is exactly the block codes in the saves: the 14,089 of the 1.22.7 world, and the 14,781 of the larger one created with Primitive Survival, beside `air` and `mantle`, which the game registers itself. *(Verified (1.22.7): both worlds' `BlockIDs`, code by code.)*

## Block colours

The game's map, in its default mode, colours each block from a palette of a dozen colours, picked by a colour code (step 4 of [How the game draws its own world map](rendering.md#how-the-game-draws-its-own-world-map)). A block's colour code is its `mapColorCode` attribute, or else its block material's default:

| Material | Colour code |
| --- | --- |
| Soil, Ore, Stone | `land` |
| Sand, Gravel | `desert` |
| Leaves, Wood | `forest` |
| Plant | `plant` |
| Snow, Ice | `glacier` |
| Water | `lake` |
| Lava | `lava` |
| anything else | `land` |

A block type that names no material is `Stone`. The palette, as the game has it: `land` #AC8858, `desert` #C4A468, `forest` #98844C, `plant` #808650, `lake`, `ocean` and `lava` #CCC890, `glacier` #E0E0C0, `settlement` #856844, `road` #805030, `devastation` #755C3C, and `ink` and `wateredge` #483018 for outlines. *(Source: vsessentialsmod [`ChunkMapLayer.cs`](https://github.com/anegostudios/vsessentialsmod/blob/06673b67318e002332b6aa8b3d0308f11d2aba99/Systems/WorldMap/ChunkLayer/ChunkMapLayer.cs), `defaultMapColorCodes` and `hexColorsByCode`; vsapi `Block.BlockMaterial`.)*

Both depend on the variant, through `blockmaterialByType`, `attributesByType` or a `mapColorCodeByType` inside `attributes` ([Block codes](#block-codes)). In 1.22.7 with Primitive Survival, of 14,781 blocks: `land` 5,400, `settlement` 4,010 (most building blocks set it), `forest` 3,634, `plant` 795, `desert` 444, `lake` 217, `glacier` 83, `ocean` 70 and `lava` 70 (the liquids), `devastation` 45 and `road` 13. Water and lake ice are `lake`, saltwater is `ocean`, glacier ice and snow are `glacier`. *(Verified (1.22.7): every block's material and colour code, against a separate implementation of the same rules.)*

## Texture colours

For accurate mode, each block's two textures are found as the game picks them (step 5 of [How the game draws its own world map](rendering.md#how-the-game-draws-its-own-world-map)), from its `textures` and `particlesTextureCode` after `…ByType` and placeholders: a texture's `base`, in the block type's domain unless it names another, is `textures/<base>.png`. A block type's `texture`, singular, is its `all`, over one in its `textures` *(Source: vsessentialsmod [`CollectibleType.OnDeserialized`](https://github.com/anegostudios/vsessentialsmod/blob/06673b67318e002332b6aa8b3d0308f11d2aba99/Loading/CollectibleType.cs#L354-L360))*; flotsam, stone paths, seagrass and kelp name theirs so. A base ending in `*` is the first file it starts, by name *(Source: vsapi [`CompositeTexture.Bake`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Client/Texture/CompositeTexture.cs))*; in which order the game lists them isn't checked. Overlays and alternates aren't used.

The game's atlas works out each texture's colours in closed code, so Storymap's are its own: the average weighs each pixel by how opaque it is, and the 30 grain colours are pixels picked at random, among those that aren't transparent, the same ones every time. In 1.22.7 with Primitive Survival, 1,730 textures colour 13,375 of the 14,781 blocks. The other 1,406, such as mushrooms, doors and multiblocks, have no texture Storymap could read; it colours them by their colour code instead of white.

## Climate and season tint

Grass, leaves and water have grey textures, which the game colours by where they are: a block type names a climate colour map and a season colour map (`climateColorMap` and `seasonColorMap`, by variant through `…ByType`; soil without grass has none), by their codes in the game's `config/colormaps.json`, which gives each an image in `textures/environment/` and its padding. In 1.22.7 there are 5 climate maps (264 × 264, a 256 × 256 map inside 4 pixels of padding, e.g. `climatePlantTint`, `climateWaterTint`) and 21 season maps (128 × 16, e.g. `seasonalGrass`, `seasonalOak`). The game's map tints in closed code (`ApplyColorMapOnRgba`); the game's shader for the world, `shaderincludes/colormap.vsh` and `colormap.fsh` in the install, does the same, and is what Storymap follows:

1. **The climate** at a column is its map region's climate map (§8 of the [save format](save-format/README.md#8-map-regions)), interpolated between its values 32 blocks apart, each channel rounded down: temperature and rainfall, each 0 to 255 *(Source: vsapi [`IntDataMap2D.GetUnpaddedColorLerped`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Datastructures/IntDataMap2D.cs))*.
2. **Height changes it:** the temperature falls by 1 for every 1.5 blocks above sea level, and rises below it; the rainfall changes by half the height above sea level, and gains 5 for each block closer than 8 above sea level, so 40 at sea level and below, each kept within 0 to 255 *(Source: vsapi [`Climate.cs`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Common/Climate.cs), `GetAdjustedTemperature` and `GetRainFall`)*.
3. **The climate colour** is the climate map's pixel at the temperature across and the rainfall down, inside the padding.
4. **The season colour** is the season map's at how far through the year it is, across. The shader picks the row, and shifts the column a little, by noise at each place; Storymap takes the column's average over its rows. It's mixed into the climate colour by a weight that's higher where it's colder: with x the temperature at ground level, 0.5 − cos(x / 42) / 2.3 + max(0, 128 − x) / 512 − max(0, x − 130) / 200, within 0 to 1. A tropical season map (`extraFlags: 1`) is weighted by rainfall instead.
5. **The tint** multiplies the block's average colour and its grain colour each, channel by channel, rounded down (`ColorUtil.ColorMultiplyEach`).

How far through the year the save is comes from `gamedata`'s clock (§6): `TotalGameSeconds` over 3,600 and `HoursPerDay` gives the day, and a year is 12 months of the world config's `daysPerMonth`. 0 is the start of January. `--season` draws a season instead, at its middle: winter mid-January, spring mid-April, summer mid-July, fall mid-October, taking spring to be March to May. The southern hemisphere, which has its seasons half a year apart, isn't handled.

Measured against a 1.22.7 world's map cache in accurate mode, water, which has no season map, matches the climate colour within 0.01 per channel: its tint is the climate map's pixel. Over grassland, the game's tint fits a climate colour and a single season colour mixed by the shader's weight, the same season colour everywhere to within 0.04, but brighter than any column of `seasonalGrass` averages, so Storymap's grass is darker than the game's. Which row and column the game picks, and how it gets that colour, is an open question. Not followed either: frost, which lightens tinted blocks where it's cold; and block classes with their own colour, such as forest floor, which mixes soil and grass by its grass level, and water lilies. A block type that names no colour maps takes those of its shape's first element naming them, as branchy leaves' and ferns' do ([Cube faces](#cube-faces), [Shapes](#shapes)). *(Measured (1.22.7): the cache divided by Storymap's untinted render, per 32-block cell, against the climate there.)*

## Cube faces

The isometric view's `game` style draws a block's top, south and east faces in its textures, for blocks the game draws as a plain cube:

- **Cubes:** drawtype `Cube` or `TopSoil`, or `JSON` (the default) with the shape `block/basic/cube` (the default) or `block/basic/cube-nozfight` (glacier ice's, its faces inset by 0.006 of a pixel), neither turned, moved, scaled nor overlaid, and with no alternates other than such a cube *(Source: vsapi [`Block`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Common/Collectible/Block/Block.cs), `DrawType` and `DefaultCubeShape`)*. Other shapes, such as stairs' and plants', and the plain cube turned, as in sand's alternates, are drawn in them ([Shapes](#shapes)); other drawtypes, such as surface layers, aren't drawn yet.
- **Liquids:** drawtype `liquid`, water, salt water, lava and the rest, on the plain cube, each face in its `all` texture; the game mixes in a second, moving one (`specialSecondTexture`), which isn't drawn. A liquid fills the whole block, even where it flows lower, and nothing shows through it.
- **Low blocks**: a block whose selection box (`selectionBox`, else `collisionSelectionBox`) reaches less than half a block high, such as loose stones, boulders, flints, ores and sticks, coral, crops and closed trapdoors, isn't drawn as a cube, as a whole cube would make it look far larger than it is, nor are plants: in the relief style they aren't drawn, and in the `game` style only in their shapes. Thin layers of the ground, snow, sand and gravel, are drawn as whole blocks. 1,974 of 1.22.7's blocks are low.
- **Leaves:** up close, leaves are crossed planes of large leaves, but the shape the game draws them in at a distance (`lod0Shape`, e.g. `block/plant/leaves/normal-lod0`) holds a plain cube, an element from 0 to 16 on every axis, in their small leaves. A block whose shape at a distance holds such a cube, unturned, is drawn as it, each face in the texture the element names for it. Branchy leaves name their colour maps on the element rather than the block type, and are tinted by those, in the coloured map too. The texture's holes take the block's average colour, tinted. 237 of 1.22.7's 245 leaves are cubes this way; narrow leaves, such as cypress's, have none.
- **A face's texture** is the one named for it (`up`, `south`, `east`), else its group's (`verticals` for top and bottom, `horizontals` for the sides), else `all`, found as for [Texture colours](#texture-colours). Its overlays are drawn over it, each stretched or shrunk to its size.
- **Variants:** a texture can have several, so a field of one block doesn't repeat one picture, in the order vsapi [`CompositeTexture.Bake`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Client/Texture/CompositeTexture.cs#L339-L452) lists them (and `Block.FastTextureVariants` for cubes): its base, or for a base ending in `*`, the first file it starts, by name, under the texture's overlays; then each of its `alternates`, the first file of the alternate's base under the alternate's own overlays, as ores show one of three overlays; then the other files its base starts, without the texture's overlays, as reef ledges' coral shows its overlay only on the first of 32. A block shows the variant its position picks, by vsapi's position hash, [`GameMath.MurmurHash3Mod`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Math/GameMath.cs)`(x, y, z, count)`, the same for every face, with y as 0 for a block type whose `randomizeAxes` is `xz`, so a tall plant shows the same variant all the way up; a layer with fewer variants than the block's others counts round again. The game picks in closed code, so whether it hashes the same way isn't checked. A variant that can't be read is left out.
- **Tint:** a block with a climate or season colour map has every face tinted, except grassy soil (drawtype `TopSoil`: soil, forest floor, peat, clay), which is its soil's texture with grass over it. The grass is its `specialSecondTexture`, twice as wide as high: the right half is the top, the left half the sides' fringe. Only the grass is tinted.

In 1.22.7 with Primitive Survival, 2,307 of the 14,781 blocks are cubes, 352 of them liquids, with 2,961 distinct face images; 1,248 cubes have variants, up to 10.

The renderer draws each cube once, when the blocks are prepared ([Pictures](#pictures)), into a 32-pixel square ([`src/renderer/isometric.zig`](../src/renderer/isometric.zig), `pictureOf`): each pixel of a face averages its texture at 2 × 2 points across it, a 32-texel texture giving about 4 texels a pixel, and is lit as the relief style lights that face. The plain and tinted layers stay apart: where a block is drawn, its tinted layer is multiplied by the block's tint there ([Climate and season tint](#climate-and-season-tint), steps 1 to 4, at the block's own height) and drawn over the plain one by how much of each pixel it covers. Blocks that aren't cubes take their average colour times the tint.

## Shapes

Every other block of drawtype `JSON`, also `JSONAndSnowLayer` and `JSONAndWater` without their snow or water, is read in its shape ([`src/vs/BlockTypes.zig`](../src/vs/BlockTypes.zig), `Shapes`), as boxes placed in the block (`world.Shape`), and the isometric view's `game` style draws it in that shape.

- **The block type's `shape`** (vsapi [`CompositeShape`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Common/Model/Shape/CompositeShape.cs)) names a shape file, `shapes/<base>.json` in the block type's domain unless it names another, or with a base ending in `*`, several (see Alternates below). Its `rotateX`, `rotateY` and `rotateZ` turn the whole shape about the block's middle, as vsapi `MeshData.Rotate` does, then `scale` scales it about the middle and `offsetX`, `offsetY` and `offsetZ` move it; in which order the game does those three isn't checked. `quantityElements` keeps that many of the first elements, `selectiveElements` only the elements it names and `ignoreElements` leaves them out, an element by its name or its path from the top (`Stem/Leaf`), and with `/*` everything under it too. Its `overlays` add their shapes' elements.
- **An element** is a box from `from` to `to`, in sixteenths of a block, turned about its `rotationOrigin` by `rotationX`, then `rotationY`, then `rotationZ`, in degrees, and scaled by `scaleX`, `scaleY` and `scaleZ`; its `children` are placed within it, from its `from` (vsapi [`ShapeElement.GetLocalTransformMatrix`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Common/Model/Shape/ShapeElement.cs), animation version 0, and [`Mat4f.RotateByXYZ`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Math/Matrix/Mat4f.cs)). Elements are turned by any angle: 6,349 different angles in the game's block shapes. `shade: false` leaves its faces unlit, and an element naming a `climateColorMap` or `seasonColorMap` is tinted by it; a block type naming none takes the first element's (226 blocks, such as berry bushes and ferns).
- **A face** is keyed by the first letter of its name (`n`, `e`, `s`, `w`, `u`, `d`), and left out if `enabled` is false. Its `uv` is a rectangle in the shape's `textureWidth` × `textureHeight` (16 × 16 by default), or the texture's own size in `textureSizes`; without one, the face takes as much of the texture as it's big, from the corner. Which corner of the rectangle goes to which corner of the face, and how `rotation` shifts them a quarter turn at a time, follow the Model Creator, which draws shapes as the game does ([`Face.java`](https://github.com/anegostudios/vsmodelcreator/blob/653138b6dedc3b2ba064a29a3c9c4d357a983318/src/at/vintagestory/modelcreator/model/Face.java), `CubeVertices` and `cubeUVCoords`); the game's own tesselator is closed.
- **A face's texture** is named with a `#`: the block type's texture of that name, or for a face named after a side, as stairs' are, its group's (`horizontals`, `verticals`); else the block type's `all`; else the shape file's own of that name; else the block type's `sides`, as cobblestone stairs name theirs. The game picks them for blocks in closed code; what it puts on display takes them in this order (vssurvivalmod [`BEBehaviorDisplay`](https://github.com/anegostudios/vssurvivalmod/blob/849fa8cad9e392368566efc7474e73db6404a145/BlockEntityBehavior/BEBehaviorDisplay.cs#L64-L86)), and blocks show the same: snow on plank stairs, which name only `all`, is drawn in planks (VintageStory-Issues [#9794](https://github.com/anegostudios/VintageStory-Issues/issues/9794)), as it was on brick stairs and slabs until they named their shapes' `snowcover` again beside their `all` ([#4258](https://github.com/anegostudios/VintageStory-Issues/issues/4258)), while cobblestone stairs and plank slabs, which name `sides`, keep their snow. Items are drawn the other way round, their shape's own texture before their `all`. A face whose texture is none of these isn't drawn.
- **Blocks placed the same share their boxes**: a shape file placed by the same composite shape gives the same boxes, and each block only names its textures for them.
- **Alternates:** a shape with `alternates`, or whose base ends in `*`, gives a block several shapes, of which each block of it is drawn in one, picked by where it is. They're listed as vsapi [`CompositeShape.LoadAlternates`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Common/Model/Shape/CompositeShape.cs#L247-L366) lists them:
	- the shape itself, its base's first file if that ends in `*`, or the plain cube if it stands for none;
	- its base's other files, turned, scaled and picking elements as the shape does, but neither moved nor overlaid;
	- each of its `alternates`, or for one whose base ends in `*`, each file it stands for, as above. An alternate without a base takes the shape's, `*` and all, and without `quantityElements`, `selectiveElements` or `ignoreElements`, the shape's; its turn, offset, scale and overlays are its own, not added to the shape's.

	A shape listed twice is picked twice as often, as herbs' and lupins' are. A base ending in `*` stands for every shape file in its domain whose path starts with it, in folders below too, whatever its format, each then read as the game's JSON; the game lists them in no set order, and Storymap takes them by name. A block picks its shape by the hash that picks its textures' variants ([Cube faces](#cube-faces)), `MurmurHash3Mod(x, y, z, count)`, with y as 0 for an `xz` block, so with as many shapes as variants, a block's shape and variant go together. The game picks in closed code; the open-source berry bush, which draws its own shape in place of the game's once pruned, so has to pick the same, picks this way ([`BlockBerryBush`](https://github.com/anegostudios/vssurvivalmod/blob/849fa8cad9e392368566efc7474e73db6404a145/Legacy/Block/BlockBerryBush.cs#L49)). 1,718 blocks of 1.22.7 with Primitive Survival pick from several shapes, up to 40 (development plates), such as ferns, loose stones, flowers, coral and berry bushes; 86 of them, such as sand, gravel and old polished rock, pick from four plain cubes turned a quarter at a time, which turns their textures. Not drawn: the alternates of leaves, which are drawn as their cube at a distance ([Cube faces](#cube-faces)).
- **Moved off the middle:** a block type's `randomDrawOffset`, `true` for 1 or a number, moves each block of it east by (`GameMath.oaatHash(x, 0, z)` % 12) / (24 + 12 · `randomDrawOffset`) of a block and south by the same with 1 for 0, the remainder keeping the hash's sign, so by up to 11/36 of a block either way, as vsapi [`Block.GetSelectionBoxes`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Common/Collectible/Block/Block.cs) moves its selection box; that the game moves the shape by the same isn't checked. The renderer moves the block's picture by it, to the nearest pixel. 476 blocks of 1.22.7 with Primitive Survival are moved so, such as flowers, tall grass, saplings and coral.
- **Turned:** a block type's `randomizeRotations` turns each block of it about the vertical line through the middle of its place, by one of 8 angles, −22.5° + 45° · i from east towards north, as vsapi [`TesselationMetaData.randomRotations`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Client/API/ITesselatorAPI.cs#L13-L30) lists them, with i picked by where it is: `MurmurHash3Mod(−x, y, z, 8)`, with y as 0 for an `xz` block. That's the hash that picks its variant ([Cube faces](#cube-faces)) at −x, so a block's turn and variant don't go together. The game turns blocks in closed code; the open-source crop prop, a decorative crop that draws its own shape in place of the game's, turns it this way ([`BEBehaviorCropProp`](https://github.com/anegostudios/vssurvivalmod/blob/849fa8cad9e392368566efc7474e73db6404a145/BlockEntityBehavior/BEBehaviorCropProp.cs#L307)). The renderer draws such a shape in each of the 8 turns. 727 blocks of 1.22.7 with Primitive Survival are turned so, such as coral, crops, flowers and mushrooms.

In 1.22.7 with Primitive Survival, 11,820 of the 14,781 blocks have shapes this way, 21,749 with their alternates, the same file placed the same way 3,620 times over, in 67,198 boxes, up to 722 for one shape; 57 of the textures their faces name are none of the above. 173 more blocks have shapes with nothing to draw (`block/basic/nothing`, `block/basic/invisible`). About 38% of the boxes the blocks are drawn in reach outside their block, such as plants' turned planes. Not followed yet: elements placed on another's by `stepParentName` (17), shapes in other formats than the game's JSON (4), and elements' `disableRandomDrawOffset`, which leaves an element neither moved nor turned (vsapi [`ShapeElement`](https://github.com/anegostudios/vsapi/blob/63d33f70018c606fb0f70ead900fe90625fbd7b2/Common/Model/Shape/ShapeElement.cs#L104-L108)), in 2 shape files, papyrus in ice, that no block uses. The drawtypes read without a shape: `SurfaceLayer` (336 blocks), `Cross` and `CrossAndSnowlayer` (28) and `BlockLayer` (15).

The renderer draws a block's shape into its own picture ([`src/renderer/isometric.zig`](../src/renderer/isometric.zig), `shapePicture`), once, when the blocks are prepared ([Pictures](#pictures)).

- **Faces** are drawn as two triangles each, at 2 × 2 points for each pixel, nearer covering farther within the block ([`src/renderer/rasterizer.zig`](../src/renderer/rasterizer.zig)). A point shows the texel there, if it's at least half opaque, so a plant's leaves leave the gaps between them. A pixel shows if at least half its points do, in their average colour, plain and tinted layers apart, as a cube's are.
- **Light** is a cube's, top, south and east, mixed by how much the face faces up, south and east; a face turned away from the viewer, as a leaf seen from behind, is lit as though turned towards it. An element with `shade: false` is lit as a top.
- **Parts outside the block** are drawn too, such as the tips of plants wider than their block, up to a block beyond the cube's square each way, the picture trimmed to what it shows. In the game's block shapes the larger test world has, most pictures stay in their square or reach a pixel or two beyond it; ferns and tall grasses reach up to 30. A tile draws the blocks on lines of sight up to a block beyond its edges too, so a picture reaching into it isn't cut there; that costs no time measurably, as encoding takes most of it.
- **Depth:** each pixel of a picture keeps how far into its block its point is, x + y + z, as a cube's pixels do by the face they're on, and a tile keeps each pixel's depth in 256ths of a block, so a part reaching into a neighbour's square shows in front of or behind it as it is. A cube's faces are never less than a 64th of a block apart at the middle of a pixel, so cubes alone come out the same as when a whole block's x + y + z ordered them. Only a part reaching out from behind a block that hides the rest of it on the same line isn't drawn, as the line stops there.
- **What's behind shows:** a line of sight goes on past a block whose picture doesn't cover the whole square, and draws the blocks behind it where it shows nothing, down to one that covers it.

Drawing shapes made the larger test world's isometric view about 11% slower, measured against the same render without them, and drawing their parts outside the block about 8% more, most of it in encoding the added detail.

## Preparing blocks

Everything a map needs from the assets is prepared once, by [`src/vs/Prepared.zig`](../src/vs/Prepared.zig), into a blocks folder: `blocks` in the current folder, beside a render's `out`, or the one given (`--blocks` when rendering, the folder argument of `storymap prepare`). For each block, that's its code, its material, its colour code ([Block colours](#block-colours)), its texture colours ([Texture colours](#texture-colours)), its colour maps ([Climate and season tint](#climate-and-season-tint)), its cube faces and how high it reaches ([Cube faces](#cube-faces)), and its shape ([Shapes](#shapes)), in `<blocks folder>/<key>/blocks.txt`, 24 MB for 1.22.7 with Primitive Survival, most of it the shapes' boxes. The colour maps' images are beside it in `colormaps/`, and the face images in `textures.bin`, as RGBA pixels (22 MB). Only drawing the blocks' pictures ([Pictures](#pictures)) needs the face images and the shapes, so a render leaves them out, and loads the rest in about 0.03 s.

- **One set per game and mods:** the key changes with the game version and the mods (their names, sizes and times), so updating either prepares a new set, and switching back finds the old one.
- **On demand:** a render prepares the set it needs if it isn't there yet. `--prepare` prepares it again anyway, and `storymap prepare` does only that.
- **Without the game**, a render uses the newest set prepared before, so a set copied from another machine works.
- **A save's unknown blocks are reported:** those of mods that aren't installed, and any others the prepared set doesn't have.

Preparing 1.22.7 with Primitive Survival takes about 2 s, for 14,781 blocks, most of it reading and decoding textures.

## Pictures

The isometric view's pictures of every prepared block are drawn once, beside them, in `<blocks folder>/<key>/pictures.bin` ([`src/renderer/Pictures.zig`](../src/renderer/Pictures.zig)): the game's reader prepares the blocks, and the renderer, which is all a picture depends on besides them, draws each block's cube or shape ([Cube faces](#cube-faces), [Shapes](#shapes)) in every variant of its textures, a block with several shapes in each of them, and a turned shape in each of its turns, blocks with the same faces, or the same shapes and textures turned alike, sharing pictures. A render maps the file and reads the pictures where they are, so a picture costs it neither drawing nor memory of its own, and the operating system reads in only the pages of the pictures its world has.

- **Its own version:** the file names the version of the pictures and its layout (`Pictures.version`). A render that finds it missing, or of another version, draws it again from the prepared blocks, without reading the game's assets; preparing again draws it too.
- **Laid out to be read in place:** a table of the blocks' pictures by their number in `blocks.txt`, a table of the pictures, then their pixels, everything at a multiple of its size, in little-endian order.
- **Size:** for 1.22.7 with Primitive Survival, 55,096 pictures, 195 MB, drawn in about 5 s; without the shapes' alternates, it was 108 MB, and without their turns too, 88 MB.
