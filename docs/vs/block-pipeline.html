The block pipeline

How Storymap turns a block type from the game's assets into the block a render knows and the sprite the isometric view draws it with. The real code is src/vs/BlockTypes.zig, src/vs/Prepared.zig, src/renderer/isometric.zig and src/renderer/Sprites.zig; blocks.md has the rules and their sources.

counted in1.22.7Primitive Survival

    1One block type

    The game defines its blocks in data files, not code: a block type is a JSON file in a domain's blocktypes/ folder, naming the block's variants, its material, its shape and its textures. The one below is made up, with the keys the game's use. The page follows it through to its sprites.

    {
	code: "plinth",
	variantgroups: [
		{ code: "rock", loadFromProperties: "block/rock" },
		{ code: "cover", states: ["free", "snowy"] },
	],
	blockmaterialByType: { "*-snowy": "Snow", "*": "Stone" },
	attributes: { mapColorCodeByType: { "*-snowy": "glacier", "*": "settlement" } },
	shapeByType: {
		"*-free": { base: "block/plinth", alternates: [{ base: "block/plinth-worn" }] },
		"*-snowy": { base: "block/plinth-snowy" },
	},
	textures: {
		all: { base: "block/stone/rock/{rock}*" },
		sides: { base: "block/stone/cobble/{rock}" },
	},
	randomizeRotations: true,
}

    2From one type to its blocks

    Variant groups multiply. Each gives a list of states, its own states or a world property's (loadFromProperties: "block/rock" is worldproperties/block/rock.json), and the type makes one block for every combination, its code the type's code and its states joined with -: plinth-granite-free, plinth-granite-snowy, plinth-sandstone-free and so on, two per rock the property lists. Groups that add instead give one block per state, an empty state adds nothing to the code, and skipVariants and allowedVariants then filter the codes, by exact code or by wildcard.

    …ByType properties give a value per variant: the first key matching the block's code wins. * matches any run of characters, a key starting with @ is a regular expression, and an object merges into one already there. In blockmaterialByType above, plinth-granite-snowy matches *-snowy first and is Snow; every other block falls through to * and is Stone. A {rock} in any string is the block's state of the rock group, so the all texture's base is block/stone/rock/granite* for the granite blocks.

    The map colour the game's own map draws a block in comes from a colour code: the block's mapColorCode attribute, or without one its material's default. Soil, ore and stone are land, sand and gravel desert, leaves and wood forest, plants plant, snow and ice glacier, water lake, lava lava, and anything else land; a block type that names no material is Stone. The code picks a colour from the game's small palette:

    land desert forest plant lake, ocean, lava glacier settlement road devastation ink, wateredge
    blockmaterialcolour code
    plinth-granite-freeStonesettlement
    plinth-granite-snowySnowglacier
    plinth-sandstone-freeStonesettlement

    Expanded this way, the game's and Primitive Survival's block types give exactly the codes a save names: 14,089 blocks for 1.22.7, and 14,781 with Primitive Survival, beside air and mantle, which the game registers itself. Of the 14,781, 5,400 are land, 4,010 settlement, which most building blocks set, and 3,634 forest.

    3Its textures

    A block type names its textures by role, and each names a file: its base, in the block type's domain unless it names another, is textures/<base>.png. A base ending in * stands for the files it starts, by name. A block type's texture, singular, is its all, over one in its textures; flotsam, stone paths, seagrass and kelp name theirs so.

    namefaces
    allevery face without a nearer name
    horizontals, verticalsthe four sides; the top and bottom
    up, down, north, east, south, westone face each
    sidesa shape's faces that nothing else names, last of all
    any other, such as snowcovera shape's faces naming it

    For the coloured map, Storymap keeps two colours of each block, from the textures the game picks them from: an average colour, weighing each pixel by how opaque it is, and 30 grain colours from its particle texture (particlesTextureCode), pixels picked at random among those that aren't transparent, the same ones every time. For a base ending in * the first file counts, and overlays and alternates don't. In 1.22.7 with Primitive Survival, 1,730 textures colour 13,375 of the 14,781 blocks; the other 1,406, such as mushrooms, doors and multiblocks, have no texture Storymap could read, and are coloured by their colour code instead.

    For the sprites, a texture can have variants, so a field of one block doesn't repeat one sprite, in the order the game lists them: its base, or for a base ending in * the first file it starts, under the texture's overlays; then each of its alternates, the first file of the alternate's base under the alternate's own overlays, as ores show one of three overlays; then the other files its base starts, without the texture's overlays, as reef ledges' coral shows its overlay only on the first of 32. The plinth's block/stone/rock/granite* gives it as many variants as there are files starting so. A variant that can't be read is left out. Which one a block shows is picked by where it is (6).

    Sources: blocks.md: texture colours · blocks.md: cube faces

    4Cube or shape

    A cube is a block of drawtype Cube or TopSoil, or of JSON, the default, with the shape block/basic/cube, also the default, or glacier ice's block/basic/cube-nozfight, neither turned, moved, scaled nor overlaid, and with no alternates other than such a cube. Liquids are drawn on the plain cube, each face in their all. Leaves are crossed planes up close, but the shape the game draws them in at a distance (lod0Shape) holds a plain cube in their small leaves, and a block whose shape at a distance holds such a cube is drawn as it: 237 of 1.22.7's 245 leaves. A low block, whose selection box reaches less than half a block high, such as loose stones, ores, crops and closed trapdoors, isn't drawn as a cube, which would make it look far larger than it is, but in its shape, and so are plants; thin layers of snow, sand and gravel are drawn as whole blocks. The isometric view's game style draws a cube's sprite, its top, south and east faces, into a 32-pixel square, each pixel averaging its texture at 2 × 2 points, lit as the relief style lights that face. In 1.22.7 with Primitive Survival, 2,307 of the 14,781 blocks are cubes, 352 of them liquids.

    Everything else of drawtype JSON, also JSONAndSnowLayer and JSONAndWater without their snow or water, is read in its shape, as boxes placed in the block, and drawn in it. The block type's shape names a shape file, shapes/<base>.json in the block type's domain unless it names another. Its rotateX, rotateY and rotateZ turn the whole shape about the block's middle, scale scales it there and offsetX, offsetY and offsetZ move it; quantityElements, selectiveElements and ignoreElements pick its elements, and its overlays add their shapes' elements. An element is a box from from to to, in sixteenths of a block, turned about its rotationOrigin by rotationX, then rotationY, then rotationZ, scaled by scaleX, scaleY and scaleZ, with its children placed within it. Each of its six faces is keyed by the first letter of its name, names its texture with a #, and takes a uv rectangle of that texture, in the shape's textureWidth × textureHeight, 16 × 16 by default. The plinth's shape, made up like its block type, is two boxes, and the snowy one a layer of snow between them:

    elementfromtoits faces name
    base0, 0, 016, 8, 16#up, #down, #north, #east, #south, #west
    snow0, 8, 016, 10, 16#snowcover, all six; in plinth-snowy only
    top4, 8, 4 (4, 10, 4 on the snow)12, 16, 12as the base's

    The shape files have one texture of their own, snowcover, for the snow's faces, as the game's stairs' and slabs' do. Elements are turned by any angle, 6,349 different ones in the game's block shapes. A shape's sprite is drawn from its boxes: each face as two triangles, at 2 × 2 points for each pixel, nearer covering farther within the block; a point shows the texel there if it's at least half opaque, so a plant's leaves leave the gaps between them, and a pixel shows if at least half its points do. Parts outside the block, such as the tips of plants wider than their block, are drawn too, up to a block beyond the cube's square each way. In 1.22.7 with Primitive Survival, 11,820 of the 14,781 blocks have shapes this way, 21,749 with their alternates, in 67,198 boxes; blocks placed the same share their boxes, and each only names its textures for them.

    Sources: blocks.md: cube faces · blocks.md: shapes

    5How a face finds its texture

    A cube's face takes the texture named for it (up, south, east), else its group's (verticals for the top and bottom, horizontals for the sides), else all.

    A shape's face names its texture with a #, and the name is looked up in this order: the block type's texture of that name; for a face named after a side, as stairs' are, its group's, horizontals or verticals; the block type's all; the shape file's own texture of that name; the block type's sides. A face whose texture is none of these isn't drawn. The order explains the game's snow: plank stairs name only all, so the snow on them, whose faces name #snowcover, is drawn in planks; brick stairs and slabs were the same until they named their shapes' snowcover beside their all; cobblestone stairs and plank slabs, which name sides, keep their snow, as nothing before the shape's own snowcover matches.

    6Picked by where it is

    Several things about a block come in more than one version, and each block of it shows the one its place picks, by the game's position hash, vsapi's GameMath.MurmurHash3Mod(x, y, z, count), with y as 0 for a block type whose randomizeAxes is xz, so a tall plant shows the same all the way up. The game picks in closed code, so whether it hashes the same way isn't checked.

    1. Texture variants, in the order of 3, the same variant for every face; a texture with fewer variants than the block's others counts round again. 1,248 cubes have variants, up to 10.
    2. Shapes. A shape with alternates, or whose base ends in *, gives a block several shapes, listed as the game lists them: the shape itself, its base's first file if that ends in *, or the plain cube if it stands for none; its base's other files, turned, scaled and picking elements as the shape does, but neither moved nor overlaid; then each of its alternates, or every file one with a base ending in * stands for. An alternate without a base takes the shape's, and its turn, offset, scale and overlays are its own. A shape listed twice is picked twice as often, as herbs' and lupins' are. The count is the number of shapes, so with as many shapes as variants, a block's shape and variant go together. 1,718 blocks of 1.22.7 with Primitive Survival pick from several shapes, up to 40, such as ferns, loose stones, flowers, coral and berry bushes; 86 of them, such as sand, gravel and old polished rock, pick from four plain cubes turned a quarter at a time, which turns their textures. The plinth picks between its own shape and block/plinth-worn.
    3. Turns. A block type with randomizeRotations turns each block of it about the vertical line through the middle of its place, by one of 8 angles 45 degrees apart, from −22.5 degrees east towards north, picked by MurmurHash3Mod(−x, y, z, 8): the same hash at −x, so a block's turn and its variant don't go together. 727 blocks are turned so, such as coral, crops, flowers and mushrooms, and the renderer draws such a shape in each of the 8 turns.
    4. Moved off the middle. A block type's randomDrawOffset, true for 1 or a number, moves each block of it east and south by up to 11/36 of a block either way, by another hash of its place (GameMath.oaatHash), the larger the number the less; the renderer moves the block's sprite by it, to the nearest pixel. 476 blocks are moved so, such as flowers, tall grass, saplings and coral.

    7Climate and season tint

    Grass, leaves and water have grey textures, which the game colours by where they are. A block type names a climate colour map and a season colour map (climateColorMap and seasonColorMap, by variant through …ByType), by their codes in the game's config/colormaps.json, which gives each an image in textures/environment/ and its padding: in 1.22.7, 5 climate maps of 264 × 264 pixels, a 256 × 256 map inside 4 pixels of padding, and 21 season maps of 128 × 16. An element of a shape can name them too, and a block type naming none takes its first element's, as branchy leaves, berry bushes and ferns do, 226 blocks. The plinth names none: stone isn't tinted.

    The tint follows the game's world shader. The climate at a column is its map region's climate map, interpolated between its values 32 blocks apart: a temperature and a rainfall, each 0 to 255, which height changes, the temperature falling by 1 for every 1.5 blocks above sea level. The climate colour is the climate map's pixel at the temperature across and the rainfall down; the season colour is the season map's at how far through the year the save is, from its clock or from --season; and the two are mixed by a weight that's higher where it's colder, or by rainfall for a tropical season map. The tint multiplies the block's average colour and its grain colour each, channel by channel.

    In the sprites, the plain and tinted layers stay apart. A block with a climate or season colour map has every face in the tinted layer, except grassy soil (drawtype TopSoil: soil, forest floor, peat, clay), which is its soil's texture with grass over it, from its specialSecondTexture, twice as wide as high, the right half the top and the left half the sides' fringe; only the grass is tinted. The holes in leaves' textures take the block's average colour, tinted. Where a block is drawn, its tinted layer is multiplied by the block's tint there, at the block's own height, and drawn over the plain one by how much of each pixel it covers.

    8What preparing keeps

    Everything above is worked out once, from the assets, into a blocks folder: blocks in the current folder, beside a render's out, or the one given (--blocks when rendering, the folder argument of storymap prepare). It holds one set per game and mods, in <blocks folder>/<key>/, the key changing with the game version and the mods' names, sizes and times, so updating either prepares a new set and switching back finds the old one. A render prepares the set it needs if it isn't there yet, --prepare prepares it again anyway, and without the game a render uses the newest set prepared before. A save's blocks the set doesn't have are reported.

    Preparing takes about 2 s for the 14,781 blocks, most of it reading and decoding textures, and drawing the sprites about 5 s more. Only drawing the sprites needs the face images and the shapes, so a render leaves them out and loads the rest in about 0.03 s; it maps pictures.bin and reads the sprites where they are, under each block's index in blocks.txt, which the renderer asks the game's reader for (spritesOf), so a sprite costs it neither drawing nor memory of its own. The file names the version of the sprites and its layout: a render that finds it missing, or of another version, draws it again from the prepared blocks, without reading the game's assets.
