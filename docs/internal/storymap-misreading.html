How Storymap misread chunk blocks

Why the renderer stalled for years, and what changed. The format itself is documented in Vintage Story save format.

    1The old assumption

    Decompressing a chunk's blocks gives one list of 1,024 i32s per bit plane, and 1,024 is exactly 32 × 32. So the old code read every list as a horizontal layer of the chunk, used the list's index as the height, and treated every i32 as one block's ID.

    In fact each list is a bit plane, and each i32 holds one bit of the palette position for 32 blocks. Select a number to compare the two readings.

    2What it drew

    The old code placed number i at column i % 32 and row i / 32, as if those were x and z. In reality i % 32 is z and i / 32 is y. So each 32 × 32 tile in the old image was a side view of its chunk (z across, height increasing downwards), lit wherever any bit was set, rather than a view from above.

    3The fix

    Chunk.getBlock now reads a block by combining one bit from each plane, and the renderer scans each column from the top for the first non-air block:

    const n = (y * 32 + z) * 32 + x;
var index: usize = 0;
for (planes[0..log2(palette.len)], 0..) |plane, b| {
    const bit = (plane[n / 32] >> (n % 32)) & 1;
    index |= bit << b;
}
return palette[index];
